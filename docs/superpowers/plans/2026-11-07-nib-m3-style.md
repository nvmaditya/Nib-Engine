# Nib Milestone 3 (Style) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build spec §5 Style (scope switch with Match document, New variation, six Looks and saved looks, the handwriting picker with filters, favourites, preview text and uploaded fonts kept in IndexedDB, pens, inks, paper and effects, How natural with Fine-tune, size and spacing, and the page-count notice with Fit back), with the Style panel as a bottom sheet on phones. Every Style change is undoable, and every realism setting the engine reads stays reachable.

**Architecture:** The engine stays as it is, apart from per-hand tags in `config.js` and one new export, `drawSample`, which writes a line of text with the real glyph engine (outlines, alternates, pen, ink and every realism setting) onto its own canvas and then puts back the document's settings, layout and font engine. Every sample in Style (the current hand, each Look, each row of the picker) is drawn that way, never with a CSS font. The panel is split into section components that take the current view (`view()`: the document's settings, or the selected block's merged ones) as props and write through `setV`/`setS`/`applyStyle`, so the store's keyed history covers them and a slider drag is one `gesture`. Device-wide things (uploaded fonts, saved looks, favourites, preview text) live in the IndexedDB `prefs` store and are read at start-up, before any document is opened.

**Tech Stack:** React 19, TypeScript (strict), Vite, Tailwind v4, shadcn-style components hand-written on `radix-ui` 1.8.1 in `src/components/ui`, `lucide-react`, `sonner`, Zustand (`src/store/editor.ts`), `idb` (IndexedDB `nib`), opentype.js 1.3.4 (inside the engine), `vaul` 1.1.2 (new, Task 9), Vitest + Testing Library + jsdom + fake-indexeddb, Playwright (installed machine-wide) for `npm run smoke`.

**Spec:** `docs/superpowers/specs/2026-11-06-nib-redesign-design.md`: §5 Style in full; §1 for the realism rule; §2 for tokens and type; §7 for phones. Layout, copy and interactions the spec leaves open come from the prototype (`git show prototype/nib-redesign:prototype/nib-prototype.html`: `stylePanel`, `scopeBar`, `LOOKS`, `REALISM`, `HANDS`, `HFILTERS`, `renderSheet`, `renderHandList`, the `look` form). The roadmap row is in `docs/superpowers/plans/2026-11-06-nib-m1-foundation.md` (Roadmap after Milestone 1).

**Branch:** `nib/m3-style`, cut from `main` after Milestone 2 is merged. Tasks run in worktrees off that branch. **The controller merges each task, and at the end merges `nib/m3-style` into `main` and pushes. No task merges, pushes or deploys.**

## Global Constraints

- Product name **Nib** in all copy. The interface says **Block**, never "text box". Copy is plain sentence case, quotes and apostrophes are curly, and every string comes from the Interface copy table below.
- **Realism is non-negotiable (spec §1).** The engine's realism code does not change. The only engine edits in this milestone are Task 1's:
  - `src/engine/config.js`: a `tags` array on each `FONTS` entry. It is data the engine never reads; it lives there so each hand's tags stay beside the hand.
  - `src/engine/core.js`: the new export `drawSample`, appended, so every sample in Style is the engine's own drawing and not a CSS font. It only calls existing functions (`use`, `geom`, `computeLayout`, `segBounds`, `renderSegment`) and saves and restores the module state (`S`, `doc`, `ENG`, `SEGS`, `PAGES`). No existing function body changes.
  - The declarations for both in `types.ts` and `core.d.ts`.

  `doc.js`, `importers.js` and every other engine function stay byte-for-byte as they are. Task 10 checks this with `git diff main -- src/engine`.
- Every setting in the Realism inventory below stays reachable at its full range. Sliders use `LIMITS` exactly, with M1's steps (1; Letter spacing 0.5; Word spacing 5). Nothing the engine draws is dropped, simplified or hidden.
- Colour tokens and type as spec §2. Tailwind: `bg-surface`, `bg-surface-2`, `bg-desk`, `border-line`, `text-muted` (grey **text**; never `bg-muted`), `bg-primary`/`text-primary` and `bg-primary-soft`. UI parts come from `src/components/ui` (hand-written on `radix-ui`, because the network proxy blocks the shadcn CLI). Icons come from `lucide-react`, and messages go through `toast()` (`src/store/editor.ts`). Figtree weights are 400 for text, 500 for controls and 600 for names and titles. Every new control has a focus ring (`focus-visible:ring-2 focus-visible:ring-ring/50`).
- `wide:` (860 px) is the only layout breakpoint, and `useWide()` (`src/lib/media.ts`) is the only JS test for it.
- `vite.config.ts` keeps `base: './'`. TypeScript `strict`. New code is `.ts`/`.tsx`. The engine stays `.js` with `.d.ts`.
- **Undo.** Every document change goes through `update(fn, { history })`, the same as M2:
  - Discrete Style actions use `step(kind)`: a pen, an ink, a paper, an effect, a preset, a Look, a hand, New variation, Match document, Fit back.
  - A slider drag is one `gesture` (Task 3, `rangeSteps`), and so is one session in the colour picker. Each arrow-key press on a slider is one step.
  - The scope switch and selection are UI state (`{ save: false, layout: false }`).
  - Device preferences (uploaded fonts, saved looks, favourites, preview text) are not part of the document and are not in its undo history. A removed look's message carries its own **Undo**.
- **Storage.** IndexedDB `nib` stays at version 1 with the stores `documents` and `prefs`; no version bump. The `prefs` keys this milestone adds are `looks`, `favourites`, `previewText` and `font:<id>` (one per uploaded font). `localStorage` holds only the per-viewer fold states (`nib.styleFolds`), and every read and write of it is in try/catch.
- **Hidden stages.** Style components get document state as props from `StylePanel`, which subscribes to `version` only while its stage is active. The M2 test `a hidden stage’s panel doesn’t redraw on every change` keeps passing. Dialogs and the phone sheet in the Style stage are open only while the stage is active.
- **Dependencies.** The one new runtime dependency is `"vaul": "1.1.2"`, pinned exactly (Task 9). Its `@radix-ui/react-dialog ^1.1.1` must resolve to the 1.3.1 that `radix-ui` already installs; `npm ls @radix-ui/react-dialog` shows a single version. No other packages are added.
- **Tests.** Test-first, and the test output stays clean: no act warnings, no React or Radix console warnings (dialogs use `aria-describedby={undefined}` or a `DialogDescription`, as M2 does). Every commit leaves `npm test && npm run typecheck && npm run build && npm run smoke` passing.

## Review Focus

1. **A document that uses an uploaded font, opened on a fresh page.** `cleanSettings`/`cleanStyle` drop a font id that isn't in `FONTS`, and the next save writes that loss back. Uploaded fonts must be registered before any document is read, cleaned or opened (Home's list, opening, duplicating, undo's restore). Tests: Task 2 (`bootStyle` before `getDoc`; App opens such a document with its font).
2. **A slow slider drag, a drag that pauses longer than a second, and arrow keys.** One drag is one undo step; each key press is one; the next drag is a new one. The M1 code split a paused drag into several steps. Tests: Task 3.
3. **A Style dialog left open when the stage changes** (the picker, Save as a look, the phone sheet). Portalled content doesn't inherit the stage's `hidden`, so it would float over Write. Each closes or hides when its stage is inactive, and the picker's search survives. Tests: Tasks 4, 5 and 9.
4. **Bad font files.** That covers a file that isn't a font, a `.woff2`, a font whose outlines opentype.js can't read, the same file twice, and storage that refuses the write. Expected: a clear message and no broken hand in the list. A duplicate selects the existing font, and a refused write keeps the font for this page. Tests: Tasks 2 and 5.
5. **Fit back while a hand is still arriving, or in Only scope.** Fit back must lay out with the real font metrics (disabled until the document's fonts are ready), and in Only scope it lowers that block's letter size. Tests: Task 8.

## Design decisions

1. **Samples are drawn by the engine.** `drawSample(canvas, settings, markup, heightPx)` (Task 1) puts a one-block document (`id 'sample'`, text = one line of markup) through `use` and `computeLayout`. It keeps the first row, narrows the part to that row's width and renders it with `renderSegment` at `heightPx / segBounds(part).h`. It returns the canvas width, then restores `S`, `doc`, `ENG`, `SEGS` and `PAGES` in a `finally`. So the sample has the hand's real outlines and alternates, the pen and ink, the realism sliders and mistakes, and it changes with New variation (it uses `settings.seed`). `HandSample` (Task 3) turns plain text into markup with the M2 serializer (`toMarkup`), so `2*3` or `# x` stay literal. It fetches the hand's file with `loadFont` if needed, draws only when its key changes or the file arrives, and draws only near the viewport. The canvas sits on a tile in the paper's colour with `mix-blend-mode: multiply`, the same as the pages.
2. **Uploaded fonts reach the engine the way built-in hands do.** A built-in hand's bytes come from `loadFont` (`fetch fonts/<id>.woff` → `fontBufs`). An uploaded font's bytes are kept on its `FontCfg` as `buf`. From there `engineFor(cfg)` runs the same `opentype.parse` → `makeEngine` path (outlines from `glyph.getPath`, GSUB alternates, advances, native stroke width), and `fontReady(id)` is true. The file is kept in `prefs` under `font:<id>` as `{ id, name, buf, forms, addedAt }`. The id is the file's FNV-1a hash and length, so the same file is one font. At start-up `bootStyle()` registers every stored font (`FONTS.push`, plus a `FontFace` for the interface and the canvas fallback for scripts the glyph engine doesn't draw), then reads the saved looks. `App` waits for it alongside `bootstrapDocuments()`, so documents are always cleaned with their fonts known. A font is accepted only when `engineFor` can read its outlines.
3. **Scope.** `view()` (M1) is the panel's source: the selected block's `boxSettings` in Only scope, else `S`. Handwriting keys (`BOX_KEYS`) go to the block in Only scope through `applyStyle`. Paper, line spacing and paper effects always go to `S`, and in Only scope their headings say `shared by every page`. A Look in Only scope leaves the paper alone.
4. **Looks.** A Look is `{ id, name, v: Partial<Settings> }`. The six built-ins set exactly hand, pen, ink, paper and the four How natural values, from the prototype. A new document's defaults are exactly Exam answer. A saved look holds the 13 `BOX_KEYS` as the view shows them, plus `S.paper`. A Look is shown pressed when every value in it equals the view (paper against `S.paper`; not compared in Only scope).
5. **Page count and Fit back.** `PageCountNotice` keeps a base page count: the displayed layout's count when the Style stage is shown, or when Dismiss is pressed. While the displayed count differs from the base, it says `Now {n} (was {base})`. When the document grew, it offers `Fit back to {base}`. `fitPlan` works on copies of the settings and document:
   - It finds the largest letter size below the current one (the block's own size in Only scope, else `S.size`) at which the document takes at most `base` pages, by bisection over whole steps down to `LIMITS.size[0]`. Page count never rises as letters shrink: wrapping is greedy and every width shrinks.
   - If even the smallest size doesn't fit, it keeps that size and finds the largest line spacing that fits, down to `LIMITS.gap[0]`.
   - If nothing fits, it returns null and nothing changes.

   `fitBack` applies the plan as one step (`step('fit-back')`) and says what it changed, with Undo. It lays the real document out again before returning.
6. **Phones.** Below 860 px the Style stage shows its pages full width, and the panel is a vaul `Drawer` inside the stage (no portal), so the stage's `hidden` and `inert` reach it too. It is non-modal (the pages stay live above it), can't be dismissed, is open while the stage is active, and has snap points `['148px', 0.55, 0.94]`, starting at 0.55. At 148 px the panel's sticky header (title, New variation, scope switch, page notice) shows. The page column gets bottom padding of 160 px, so the last page can scroll clear of the sheet. The handwriting picker is a `Dialog`: a 440 px panel on the right on wide screens, a bottom sheet 85 dvh tall on phones.

## Rulings on the spec and prototype

- **Phones.** The Style bottom sheet ships in this milestone, on `vaul` 1.1.2 pinned (the spec's library). Outline's sheet stays with M6 and Export's with M4. `src/components/ui/drawer.tsx` is written so both can reuse it.
- **The picker is a dialog, not a second drawer** (no nested vaul sheets). It is styled as a side panel on wide screens and as a bottom sheet on phones, as in the prototype.
- **Filters** are one choice at a time, with `All` first (the prototype). Uploaded fonts carry no tags, so they show under `All` and `★ Favourites` only, listed first, newest first.
- **Hand tags.** Joined-up or Print follows the engine's `conn` flag (letters that join), so the filter matches how a hand is drawn. Neat and Fun follow the existing groups. Messy is a judgment on seven scrawly hands: `dawning`, `zeyada`, `loved`, `glory`, `liujian`, `justme`, `reenie`. That gives 8 joined-up, 25 print, 9 neat, 7 messy and 3 fun.
- **Uploads are TTF, OTF and WOFF only** (the spec's list). WOFF2 is refused: opentype.js 1.3.4 can't read its outlines, so the letters couldn't be reshaped. M1 accepted it and drew it with the browser's font, which drops realism. A file whose outlines can't be read is refused too. Uploaded fonts can't be removed in M3 (the spec doesn't ask).
- **Look values** come from the prototype, mapped to engine ids (prototype `cedar` = `cedarville`, `pen` = `tip`). Looks don't set letter size, spacing or mistakes.
- **Saved looks can be removed** (`Remove {name}`, with Undo). The spec doesn't say, but without it a look saved by mistake is permanent.
- **No block selected:** the switch is replaced by a line of text (the prototype). The disabled `Only this block` button from M1 goes.
- **The page notice** also says when the count went down (`Now 1 page (was 2)`), without Fit back, and both kinds can be dismissed. The count starts again each time Style is shown.
- **Fit back** follows the spec's order literally: letter size down to the smallest, then line spacing. It is disabled while a hand's file is still arriving, and when nothing fits it changes nothing.
- **As drawn.** Documents that use it keep drawing with it. No pen is shown pressed and the Pen heading shows no value, and choosing a pen leaves As drawn for good, like M1's crease.
- **Paper effects a paper can't show** are off and labelled `Not on this paper`: Room lighting on Photo (the photo brings its own light), and Punch holes on Spiral, Yellow pad and Photo (`paintPaper` draws holes only where `PAPERS[id].holes`). The fold crease keeps M1's turn-off-only switch.
- **Folds.** `Paper effects`, `Fine-tune` and `Letter and word spacing` are folds, as in the prototype. Each one's open state is remembered on the device.
- **Own style** is a badge on the block's page tag in Style, always visible for such blocks, and in Outline (M2).
