# Nib Milestone 2 (Write) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build spec §4 Write (blocks, a lossless TipTap editor, the Pages and Outline views, layout rules 1–4, every restructuring action and click-a-word) plus one-page-at-a-time Write on phones, all undoable, without touching the engine's realism.

**Architecture:** A block stays an engine box (now with `kind`, `name`, `color`, `fields`, `from`) whose text is engine markup, and `computeLayout` places parts page by page so continuations follow their start and growing blocks push lower ones down at layout time. Each typed part is a TipTap editor over whole markup lines, with a converter that keeps one markup line per leaf block, and every edit goes through the store's `update()`, so there is one undo history. Stages and Write views stay mounted after their first visit, and page canvases are drawn only near the visible viewport.

**Tech Stack:** React 19, TypeScript (strict), Vite, Tailwind v4, shadcn/ui (Radix) in `src/components/ui`, `lucide-react`, `sonner`, Zustand (`src/store/editor.ts`), TipTap 3.33.0 (`@tiptap/core`, `@tiptap/pm`, `@tiptap/react`, `@tiptap/starter-kit`, `@tiptap/extensions`, `@tiptap/extension-list`, `@tiptap/extension-blockquote`, `@tiptap/extension-highlight`, `@tiptap/suggestion`), Vitest + Testing Library + jsdom + fake-indexeddb, Playwright (installed machine-wide) for `npm run smoke`.

**Spec:** `docs/superpowers/specs/2026-11-06-nib-redesign-design.md`: §4 Write in full, and §7 for Write on phones. Layout, copy and interactions the spec leaves open come from the prototype (`git show prototype/nib-redesign:prototype/nib-prototype.html`: `renderWrite`, `renderOutline`, `typedPage`, `editorFor`, `inspector`, `blockMenu`, `pageMenu`, `addMenu`, `ACTIONS`).

## Review Focus

1. **Typing past the bottom of a page in a typed part.** The caret must not jump, and no line may show twice or vanish across the typed pages. The overflow shows on the next typed page once the editor is left. Test: Task 10.
2. **Ctrl+Z inside the editor.** One history only: the editor's text and the handwriting go back together, the caret lands at the change, and Redo works. TipTap must never undo on its own. Test: Task 6.
3. **Pasting from Google Docs and Word** (the `<b style="font-weight:normal">` wrapper, styled spans, nested lists, Word `MsoListParagraph`). Formatting arrives as markup, and nothing becomes bold that wasn't. Test: Task 6.
4. **Literal markup characters typed as text** (`2*3*4`, `snake_case`, `a==b`, a line that starts with `- `, `1. `, `# ` or `>`, a backslash). They stay literal on the handwritten page and after a reload. Tests: Tasks 2 and 4.
5. **Acting on a block while its editor has focus** (Delete block, Split, Remove part, Delete page). There must be no crash, and no late write from the unmounting editor may bring the block back. Tests: Tasks 10 and 11.

## Design decisions

1. **Typed pages edit whole lines of a part.** Each part of a block on a typed page is its own TipTap editor over a *line range* of the block's markup: the lines that *start* in that part (`partRanges`, Task 6). A paragraph that runs over a page break is edited where it starts, so marks, list items and quotes are never cut mid-line. A part with no line of its own shows `Continues the paragraph from page {p}.` While a part's editor has focus its range is frozen. Typing never re-slices it, and later parts' ranges shift by the number of lines it gained (`frozenRanges`). A live `Page {p} starts here` line inside the editor shows where the handwriting breaks. All ranges are recomputed from the layout when the editor loses focus or the block changes from outside (undo, an action). So the caret never moves under the person's fingers, and no line is shown twice.
2. **One history.** TipTap's `undoRedo` is off. `Mod-z`, `Mod-Shift-z`, `Mod-y` and `beforeinput` `historyUndo`/`historyRedo` inside an editor call the store's `undo()`/`redo()`, which then asks for the caret at the first offset where the block's text changed (`placeCaret`). Typing is one step per burst (`'type:' + boxId`, 1 s rule), gestures are one step each, and actions are one step each. **Stages and views stay mounted:** `StageHost` mounts `write`, `outline`, `style` and `export` on their first visit and then keeps them, hidden and `inert` while inactive. Editors, the Style panel's search and scroll positions therefore survive a switch (M1 deferred regression). Page canvases are drawn only while their sheet is within 150 % of the viewport of an active view and are released otherwise, so keeping stages alive costs no canvas memory.
3. **Click-a-word.** The engine's `hitWord(sg, x, y)` (Task 5) finds the row under the point (and undoes a margin note's tilt), picks the nearest word from the same widths `wrap` used, and returns `row.src`-style `{ li, tok }` (the token's `oi`). `srcOffset(text, { li, tok })` turns that into a markup offset, and `placeCaret(boxId, offset)` asks for the caret. The editor whose line range holds the offset (only in an active view) turns the offset into a ProseMirror position: line `li` is leaf block `li − range.first` (the converter guarantees one leaf per markup line), and the column comes from `rawToTextCol` (Task 4). **Outline's page-break lines** come from `frameRange(box, idx)[0]` for each part `idx ≥ 1`, mapped the same way. At a line start the line is a widget before that leaf. In mid-paragraph it is an inline widget at that character. Each line carries `Split here` and `Remove page {p} part`.
4. **Dragging with pointer events, for mouse and touch alike** (`startDrag`, Task 8). Explicit grips (page grips, name-tag grips, the hand-page `Move` grip) have `touch-action: none` and start after 4 px of movement. Outline items start after 4 px with a mouse, or after a 350 ms hold that moves under 8 px with touch; a quicker move lets the list scroll. Once a touch drag is active, a non-passive `touchmove` listener stops scrolling. Drop targets are `[data-drop-page]` elements found with `document.elementFromPoint`, and page drops use before/after by the target's midpoint. The nearest scroller auto-scrolls within 48 px of its edges, and Escape cancels. Keyboard and phone users get the same moves from ⋯ menus (`Move up`, `Move down`, `Move to page…`).
5. **Markup stays the engine's, made lossless.** The engine parser gains backslash escapes (a backslash before ASCII punctuation makes it literal). The serializer puts a backslash before each `\`, `*`, `_`, `~`, `=`, `` ` `` and `[` in text, and escapes line-start markers in top-level paragraphs. Inline marks are written by a short chain of strategies, and the first one whose parse-back matches is kept (Task 4). "Lossless" means exactly this. Canonical markup (everything the serializer writes, including the sample document) round-trips byte for byte. Any markup round-trips to markup that lays out identically. Any editor content round-trips with every non-space character keeping its marks. The one exception: an underline that starts or ends inside a word, on a line that also has bold, widens to the whole word.

## Rulings on the spec and prototype

- **Escapes in the engine's markup.** The spec's markup has no way to write a literal `*` or a literal `- ` at a line start, so the converter could not be lossless. Ruling: the engine's `parseInline` accepts backslash escapes (Task 2). Old text changes only where a backslash stands before punctuation (`\\server` would now read `\server`).
- **Header fields.** The spec lists five (Name, Class, Subject, Roll no., Date); the prototype shows three and adds Subject or Roll no. from ⋯. Ruling: all five exist, a new header shows Name, Class and Date (Date = today, `6 November 2026` style), and Subject and Roll no. are added or removed from ⋯.
- **Rule 4 message.** The spec's copy wins over the prototype's (no quotes, no "(⋯ → Split)").
- **View switch labels.** The spec says "Side by side, Typed only or Handwritten only"; the prototype's buttons say `Side by side`, `Typed`, `Handwritten`. Ruling: the prototype's labels, with the spec's meaning.
- **Moving a page that holds only continuations.** Rule 3 moves "the blocks that start on it", and such a page has none. Ruling: the move is refused with the rule-4 message for its first continuation part.
- **Join back** re-attaches the split block's text to the end of the block it came from, on a new line. It flows on from there by rule 1. A paragraph that had been cut mid-way stays two paragraphs, which looks the same on the page.
- **Margin note "small, tilted".** The engine has neither. Ruling: kind `note` lays out at 0.8× letter size and its finished part is rotated by a fixed angle between −1° and −3° (seeded per block), both in the engine so screen and download match. The strokes themselves are not changed.
- **Phones.** Write's Pages view becomes one page at a time with a Typed ⇄ Handwritten flip and swipe (Task 12). **Outline's bottom sheet waits for Milestone 6.** Until then, Outline on phones stacks the page list above the selected block's editor and hides the middle column.

`fromMarkup` maps each markup line (via `parseLine`) to exactly one leaf block, in order:
- `newpage` becomes `pageBreak`, `hr` becomes `horizontalRule`, and `blank` becomes an empty paragraph.
- `heading` becomes `heading{level}`.
- `bullet` becomes a `listItem{indent: depth}` in a `bulletList`; it joins the list just before it.
- `number` becomes a `listItem{indent}` in an `orderedList{kind, delim, start}`. It joins the list before it only when kind and delim match and its number is the next one by `listMarkers` (one counter per indent, reset by a shallower item, with the list's first indent counting from `start`). Otherwise it opens a new list with `start` = its number.
- `quote` becomes a paragraph in a `blockquote`; it joins the quote before it.
- `text` becomes a paragraph of the whole line.
- Inline content comes from `parseInline`: `bold`, `ul` becomes `underline`, `strike`, and `hl` becomes `highlight`.

`toMarkup` writes one line per leaf:
- A paragraph is its inline content. A top-level paragraph also escapes a line-start marker: after any leading spaces, `\` goes before `#` (only at column 0), `-`, `+`, `>`, and before the `.`/`)` of `\d{1,3}[.)] ` or `[a-z]) `; a rule-like line becomes `\---`.
- A heading is `#`×level + space; a bullet is `'  '`×indent + `- `; an ordered item is `'  '`×indent + its `listMarkers` marker + space.
- A quote paragraph is `> ` + content, or `>` when empty.
- `horizontalRule` is `---`, `pageBreak` is `\newpage`, and tabs are written as four spaces.

Inline content uses this chain (it is checked exhaustively below):

```ts
export function inlineToMarkup(runs: Run[]): string {
  const cs = chars(runs);                                   // one entry per character, with its mark set
  for (const write of [() => nest(cs, 'star'), () => nest(cs, 'edge'), () => perWord(cs)]) {
    const md = write();
    if (sameWords(parseInline(md), cs)) return md;          // parse back with the engine's own parser
  }
  return perWord(widenUnderline(cs));                       // always parses back
}
// nest(cs, ul): walk runs of equal marks. Close the open marks the run lacks, and every mark opened after them.
//   Open the run's new marks longest-reaching first (ties: underline, bold, strike, highlight); write the run's
//   leading whitespace before the delimiters it opens. Delimiters ** ~~ ==; underline '*' ('star'), or in 'edge'
//   '_' when both ends of the underline sit at a word boundary and '*' otherwise. Text escapes \ before \ * _ ~ = ` [.
// perWord(cs): whitespace as it is; each word written with nest(word, 'edge') on its own, so no mark spans a space.
// widenUnderline: an underline that starts or ends inside a word grows to cover the whole word.
// sameWords: same text, and every non-whitespace character carries the same marks.
```

// inside boxParts(box, g, cfg, out), a generator:
//   const at = yield { page, idx, x, w, top };   // where the part would go: box.y / frame y / g.top, page = previous part's page + 1
//   seg = { box, page: at.page, idx, x, w, top: at.top, storedTop: top, pushed: at.page !== page || at.top !== top, rows: [] }; out.push(seg);
function computeLayout() {
  const g = geom(), out = [], queue = new Map();               // page -> parts waiting to be placed on it
  const wait = (p, c) => { if (!queue.has(p)) queue.set(p, []); queue.get(p).push(c); };
  const resume = (c, at) => withBox(c.box, () => c.gen.next(at));
  doc.boxes.forEach((box, order) => {
    const c = { box, order, gen: withBox(box, () => boxParts(box, g, fontCfg(), out)) };
    c.req = resume(c).value; wait(c.req.page, c);
  });
  for (let p = 0; queue.size; p++) {
    const here = (queue.get(p) || []).sort((a, b) => a.req.top - b.req.top || (b.req.idx > 0) - (a.req.idx > 0) || a.req.x - b.req.x || a.order - b.order);
    queue.delete(p);
    const placed = [];
    for (const c of here) {
      let top = c.req.top;
      if (p < 1000) for (const s of placed) if (s.x < c.req.x + c.req.w && c.req.x < s.x + s.w) top = Math.max(top, lastRule(s, g));
      if (top > c.req.top && top + g.gap > g.maxBase) { wait(p + 1, { ...c, req: { ...c.req, top: g.top } }); continue; } // pushed off the page
      const r = resume(c, { page: p, top }), seg = out[out.length - 1];               // this part, now filled
      if (seg.idx > 0 && !seg.rows.length) out.pop(); else placed.push(seg);
      if (!r.done) wait(r.value.page, { ...c, req: r.value });
    }
  }
  // lastRule(s, g) = s.rows.length ? last row's ruleY : s.top + g.gap; set bottoms as today; sort out by (box order, idx); SEGS = out; PAGES as today
}
